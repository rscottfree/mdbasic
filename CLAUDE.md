# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MDBASIC is an extension to Commodore 64 BASIC V2, written in 6502 assembly. The entire runtime is one file, `mdbasic.asm` (~9,500 lines), assembled with TMPx/Turbo Assembler into a 8K image that occupies `$8000-$BFFF` on the C64. It adds new keywords (sprites, graphics, SID sound, disk commands, structured editing) and overrides several BASIC ROM vectors to hook tokenization, listing, and execution.

## Build & run

All tooling assumes `tmpx` (TMPx assembler), `x64sc` (VICE emulator), and `c1541` (VICE disk tool) are on `PATH`. Download TMPx from https://style64.org/file/TMPx_v1.1.0-STYLE.zip.

- `sh compile.sh` — assemble `mdbasic.asm` → `mdbasic.prg` (+ `mdbasic.lst`), then launch VICE and `SYS64738` to install. The primary build+run loop.
- `tmpx -l mdbasic.lst -i mdbasic.asm -o mdbasic.prg` — assembly only, to verify the source builds without launching the emulator. The `.lst` listing file is the best reference for resolved addresses.
- `sh runcart.sh` — run the prebuilt `mdbasic.crt` cartridge in VICE with `mdbasic.d64` mounted on drive 8.
- `tools/build_disk.sh [outdir]` — assemble and write all release artifacts to `outdir` (default `build/`): `mdbasic.prg`, `mdbasic.d64` (template copy with the fresh PRG), `mdbasic.d81` (fresh 1581 disk mirroring the D64), and `mdbasic.crt`. Assembles `mdbasic.asm` as-is (no version or color stamping).
- `tools/make_crt.py prg crt` — wrap a 16K MDBASIC PRG into the Magic Desk cartridge (CRT hardware id 19). MDBASIC runs from RAM and pages BASIC ROM in/out, so it can't run from a plainly mapped cart; the loader (`tools/cart_boot.bin`, generated from `boot.asm`) copies the image from banked ROM into `$8000-$BFFF`, disables the cart, and restarts via the copied "CBM80". Given `--pager/--index/--data/--handler`, it also appends the docs-pager banks (3+) and the loader installs the RESTORE docs handler (see Docs pager below). `tools/make_crt.py`'s docstring documents the bank layout.
- **CTRL+RESTORE menu (docs pager + renum/move tool):** pressing CTRL+RESTORE opens a tiny menu — **F1** the full-screen docs viewer, **R/M/C** the in-place BASIC renumber/move/copy tools, **P** the program packager (next bullet), **F7** the number-base converter — all bundled into extra Magic Desk banks, costing ZERO bytes in the 16K image. The RESTORE NMI fires on every RESTORE; the handler gates on CTRL (keyboard-matrix row 7 / `STKEY` $91 bit 2, which `SCNSTOP` already latched for the STOP test): RUN/STOP+RESTORE breaks, CTRL+RESTORE shows the menu, and plain RESTORE keeps its editor-mode-reset/no-op behaviour. `menu.asm` is the `$033c` NMI stub: it gates, then uses a shared `copyrun` (page a bank → copy N pages to `$c000` → JMP, with N set per-caller: 3K for the docs pager, 6K for the renum tool, 512B for the menu-body) to first run the `menu_body.asm` UI (drawn at `$c000`, returns the menu choice) and then the chosen tool (also `$c000`, over the menu-body); each tool RTSs back and the stub does the single NMI-tail RTI. `menu.asm` also has direct `dodocs`/`dorenum`/`domove`/`docopy`/`doconvert`/`dopack` entries that the tests SYS to, past the gate. `renum_tool.asm` is the renumber/move/copy REPL (`R [inc] [start] [end] [dest]`, `M start end dest`, `C start end dest`, RUN/STOP exits) — it runs entirely at `$01=$37` (ROM in), validates every op with a pre-flight pass that rejects before mutating (so a rejected R/M/C leaves the program byte-identical), and reuses MDBASIC's RENUM reference-scanner + in-place digit resize (`nocrap`/`sav7a`/`numchr`/`inc2d`/`dec2d`) with its own old→new mapping (`mapnum`); MOVE physically relocates the block by a 3-reversal in-place swap, then `LINKPRG`s. COPY's pre-flight (`val_copy`) is move's validation minus the "skip source lines" carve-out in the collision scan — a copy leaves the source in place, so the destination range must not overlap it either, not just other lines. `cp_reserve` finds the source block and its sorted insertion point, opens a gap of exactly that many bytes by shifting everything from the insertion point to `STREND` up in one descending pass (bumping `VARTAB`/`ARYTAB`/`STREND` by the gap size so the reference-scanner's own `inc2d`/`dec2d` growth, run next, shifts against the right new top), and duplicates the source's raw bytes into the gap. `refpass_blk` is a second entry point into the same reference-scanner body as `refpass` (renum/move's whole-program pass): it starts at the fresh duplicate's address instead of `TXTTAB` and stops after exactly the source line count instead of at the program's `$0000` link — so it retargets only the copy's *internal* references (ones whose number falls in the original source range get the same old→new offset as MOVE's `mapnum`) and never touches the untouched source block or the rest of the program. `hdr_copy` then renumbers just the duplicate's own line headers, walking by content-scan (`lp_next_scan`) since the duplicate's link fields are still stale copies of the originals' until the closing `relink`. Its `readline` reads raw `GETIN` (not the KERNAL screen editor), so it forces the cursor blink off (`BLNSW`, same flag/idiom as the docs pager) for the REPL's duration, and its input filter takes plain printable PETSCII ($20-$7f) plus DEL/RETURN/RUN-STOP but drops the $80-$9f shifted control range (cursor keys, RVS, colour, f-keys) so there's no visible cursor to blink and no way to move one around the screen. **Screen/cursor/blink snapshot is centralized in `menu_body.asm`, not duplicated per tool:** `menu_body.asm` is the only place that snapshots screen RAM (`savescreen`/`SCRBUF` at `$cc00`) + cursor position (`PNTR`/`TBLX`/`PNT`) + the prior blink-enable state, into a shared zero-page handoff (`SAVD3`/`SAVD6`/`SAVPNT`/`SAVHIB`/`SAVBLN` at `$06-$0d`, picked clear of `copyrun`'s own transient scratch `$02-$05`/`$fb-$fe` and of `renum_tool.asm`'s/`docs_pager.asm`'s persistent zero page). `renum_tool.asm` and `docs_pager.asm` never save on entry, only restore from that handoff on exit -- restoring `PNT` too, even in `docs_pager.asm`, which never disturbs `PNT` itself but must undo `menu_body.asm`'s own `CLRSCR` homing it upstream. `menu.asm`'s `runmenu` always runs `menu_body.asm` before any tool: the real CTRL+RESTORE path (`domenu`) sets `SAVEONLY=0` for the full F1/F3/STOP UI; the `dodocs`/`dorenum` test-bypass entries set `SAVEONLY=1` so `menu_body.asm` skips the UI and just takes the snapshot before returning, so the tool that runs next (without ever seeing the menu) still has one to restore from. On F1/F3, `menu_body.asm` leaves the restore to the dispatched tool's own exit rather than restoring-then-re-saving; on STOP (dismiss) it restores itself, since no tool follows. If entry wasn't the plain `$0400` text screen (`SAVHIB != $04`, e.g. a SCREEN 1-5 page), the snapshot isn't meaningful, so exit falls back to the docs pager's SCREEN-1-5 idiom: clear to a fresh screen under `SEI` with `GDCHAR`/`BLNON` reset. `RENUM_BANK` is appended as the last cart bank (so `DATA_BANK0=4` / pager bank math are unchanged) and holds the renum tool at `$8000` (up to `MENU_OFF`, 6K — grown from the docs pager's 3K `PAGER_MAX` convention once the tool's COPY command outgrew it) + the menu-body at `$9800`; its bank number varies with the doc-data count, so `make_crt.py` patches it into `menu.asm`'s `renumbank` byte (offset 3). `menu.asm`'s `lpager`/`lrenum` set the `copyrun` page count (`X`) per tool before the shared `launchtool`/`copyrun` dispatch (12 pages for the docs pager, matching `PAGER_MAX`; 24 for the renum tool, matching `MENU_OFF`) rather than one size shared by both, since the two banks' first-region budgets diverged; `runmenu`'s menu-body copy stays a fixed 2 pages/512B (ample headroom over its ~350-byte size) from the bank's `MENU_OFF`. **`menu.asm`'s size is capped by `boot.asm`'s `HANDLER_LEN`** (the fixed byte count the loader copies from cart bank 3 to `$033c` at boot) -- grow `menu.asm` and you must bump `HANDLER_LEN` in `boot.asm` (and the mirrored constant in `tools/make_crt.py`, which fails the build if the assembled handler exceeds it), or the boot copy silently truncates its tail. `tools/build_docs.py` extracts `mdbasic.pdf` into fixed 40-col line records + a topic index; `docs_pager.asm` is the viewer (runs at `$c000`); `boot.asm` is the loader source (it repoints the cart NMI vector `$8002` -> `$033c`, copies `menu.asm` there, and stashes the original `runstp`). `tools/vice_renum_test.py` drives the tool (menu F1/F3, renumber/move success, reference rewrite with digit grow+shrink, reject paths byte-identical, REPL persistence, post-op link-integrity + executability). `tools/vice_docs_test.py` is the end-to-end pager test (boot, install, `SYS dodocs` past the CTRL gate, search, exit, sprite_timing regression); `tools/vice_docs_nav_test.py` supplements it with the doc-view navigation keys (F3/F5 topic nav, F7/F1 paging, HOME, DEL, selection highlight, status bar); `tools/vice_docs_clobber_test.py` proves the pager overwrites `$c000-$cfff` (SCREEN pages / bitmap color / RS-232 buffers) — it assumes that 4K is free scratch — and that the exit forces a canonical text mode / VIC bank 0 (VMCSB `$15`, SCROLY text, bank 0) rather than half-restoring the pre-docs graphics state, so a graphics program recovers cleanly by re-`RUN`ning. `tools/vice_docs_cursor_test.py` covers a related editor-state fix: exiting from a SCREEN 1-5 page must leave the cursor visible — that page's screen RAM was never saved (SCRBUF only holds `$0400`), so its stale line-link table / `PNT` ($d1/$d2) would leave the cursor drawn off-screen until a keypress; the exit clears to a fresh `$0400` screen (rebuilding the link table + homing `PNT`) when `savhib != $04`, while page 0 keeps its restored screen. The clear + cursor reset runs under `SEI` and explicitly sets `GDCHAR`/`BLNON` to a clean "no block, space underneath" state: on the Ultimate 64 the cursor-blink IRQ runs at turbo speed and otherwise races the clear (draws a block at the old `PNT`, flips `BLNON`, then `CLRSCR` homes `PNT` leaving `BLNON` stale, so the next keypress stamps a stray char at the homed cell). The test freezes the true pager-exit state by returning the synthetic NMI frame into a `SEI`+JMP-self spin loop (interrupts masked, no blink; a real CTRL+RESTORE RTIs back to the interrupted editor loop, never through READY, so READY can't re-init `PNT` for it) and asserts `PNT`/`GDCHAR`/`BLNON` plus the canonical VIC state. The docs-pager design memory has the full mechanism.
- **P=PACKAGE (standalone auto-run PRGs):** `pack_tool.asm` (menu key P, a cart tool run at `$c000`) writes MDBASIC + the BASIC program in memory as ONE PRG on the current drive (`$ba`, floor 8; an existing file is scratched first): `LOAD"NAME",8,1` on a stock, cartridge-less C64 auto-runs it exactly like install+LOAD+RUN, no reset. Packaged-file layout (load address `$0302`): the first word retargets IMAIN (`$0302`) at the boot stub; `$0304-$0333` streams the standard vector values over themselves (safe mid-load: every byte written equals the live byte, IRQ vector included); the stub sits in the cassette buffer `$0334-$03ff`; a banner screen fills `$0400-$07ff`; the program loads at its final `$0801`; the 16K image follows immediately after the program (under the BASIC ROM for large programs — never into I/O space, since VARTAB <= `$8000` caps the file end at `$c000`). After the direct-mode LOAD, BASIC relinks (the program's own end marker stops the walk before the image), prints READY, and jumps through IMAIN -> stub: restore IMAIN, strictly-descending copy of the image to `$8000-$bfff` (dst >= src always, any program size), set TXTTAB/VARTAB, install MDBASIC the way `resvec` does on a warm machine (`jsr newvec` + `initclk` with BASIC ROM paged out), then stuff RUN+RETURN into the keyboard queue (after `newvec` — its `initmdb` clears the queue) and enter the main loop, so execution takes the same path as a hand-typed RUN. `pack_stub.asm` is the stub source; its `$caf1`/`$caf2` jsr sentinels are patched to the real `newvec`/`initclk` (read from `mdbasic.lst` — keeping `mdbasic.asm` untouched) by `make_crt.py` inside the assembled tool binary, which embeds the stub via the generated `build/pack_stub.inc` (`tools/bin2inc.py`). At package time the tool patches only the stub's progend word and, while streaming `$8002/$8003`, substitutes the original `runstp` from REALGONE if the boot loader had repointed the cart NMI vector at the `$033c` menu handler — so the emitted image is byte-identical to the pristine build. Sprite/font data files are NOT bundled: the packaged program LOADs them at runtime from the disk it started from, so ship them alongside. The PACK bank is appended after CONVERT (`toolbanks` offsets 3..7). `tools/pack_prg.py` is the host-side twin/oracle producing byte-identical files; `tools/vice_pack_test.py` covers menu wiring, oracle byte-compare, overwrite, runtime data files, and cartless auto-run output equality against a hand-typed reference RUN; `tools/vice_pack_examples.py` packages the example-program sample into `build/packaged.d81` with the real in-emulator tool and verifies each. VICE 3.10 gotchas handled there: pass `-default` (a user vicerc can hang cart+disk serial), `-drive8type 1581` for D81s, and poll the binary monitor over short-lived connections (an open connection pauses the machine).
- `tools/vice_cart_test.py crt` — boot a `.crt` headless in VICE and assert the MDBASIC banner.
- For Ultimate 64 manual testing, run `tools/build_disk.sh`, then mount the fresh disk with `$HOME/.local/bin/u64 create mount -t local -p /Users/ryan/Developer/mdbasic/build/mdbasic.d64 -d a -s`. Slot `a` is device 8. If the mount/test path behaves stale or unreliable, ask the user to reset the U64 before continuing.

## Testing

There is no unit-test framework — testing means assembling, then running BASIC in VICE and asserting on screen RAM. The harness in `tools/` automates this:

- `tools/c64_basic_prg.py [--dialect mdbasic] src.bas out.prg` — tokenize ASCII BASIC into a real `$0801` PRG. The `--dialect mdbasic` mode emits MDBASIC extension tokens. Use this instead of `petcat` (petcat misreads uppercase ASCII as shifted PETSCII).
- `tools/vice_prg_test.py --file name=host.prg --run name --expect "TEXT"` — build a temp D64, boot `x64sc`, inject `LOAD`/`RUN` over the binary monitor, and poll screen RAM for expected text.
- `tests/sprite_timing.bas` validates `MOVE ... TO ...` jiffy-clock timing; it writes result bytes to `$C000-$C002`. `tools/u64_sprite_timing_test.sh` runs the same check against the `c64ultimate` hardware.

See `tools/README.md` for full harness usage.

## How MDBASIC installs and runs

The image at `$8000` begins with a cartridge header (`.word resvec,runstp` + `"CBM80"`), so it can be installed as a cartridge or loaded as a PRG and started with `SYS64738`. Two entry paths set up the same state via `newvec`:

- `SYS64738` (reset / `resvec`) — full cold start, shows banner, enters immediate mode.
- `runstp` — Restore-key NMI handler / break path.

MDBASIC works by overriding BASIC's indirect vectors: `ICRNCH ($0304)` for tokenizing, `IQPLOP ($0306)` for listing, `IGONE ($0308)` for execution. `R6510` ($01) is toggled throughout to page the BASIC ROM in/out so the `$8000-$BFFF` RAM image is visible when needed.

## Adding or changing keywords (the critical structure)

New keywords are defined by a set of parallel tables near the top of the image (around lines 391-640 in `mdbasic.asm`). To add a keyword you must keep these in sync, in token order:

1. **`newcmd`** — keyword name strings as `.shift` entries (last char has bit 7 set). Order defines token assignment.
2. **Token constants** (`TOKEN_*`, lines ~341-389) — MDBASIC tokens start at `FIRST_CMD_TOK = $cb`. Statement/command tokens, then statement+function tokens (`ERR`/`KEY`/`TIME` at `$f2-$f4`), then function-only tokens (`$f5-$ff`, with `PI` = `$ff`).
3. **`cmdtab`** — command dispatch table (`.rta` per token, `$80` upward). Entries reuse CBM ROM routines or point at MDBASIC routines; `.rta REM` is used for no-ops like `ELSE`.
4. **`funtab`** — function dispatch table for the function tokens `$f2-$ff`.

Tokenization (`toknew`, from ~line 644) and listing/de-tokenizing must round-trip these consistently. The keyword tables, token constants, and dispatch tables are positionally coupled — an off-by-one between them silently corrupts dispatch.

Custom MDBASIC error messages are appended after the CBM error list (`misop` etc., tokens 31-37) with the `erradd` pointer table; raise via `ldx #errno : jmp ($0300)`.

## Conventions

- Match the surrounding style in `mdbasic.asm`: existing label naming, column alignment, and comment density. Comments explain hardware/intent, not individual opcodes. Zero-page, KERNAL, and VIC/SID register equates are all defined and commented at the top of the file — reuse them rather than hardcoding addresses.
- Generated artifacts are gitignored, not committed: `tools/build_disk.sh` writes them to `build/` (also `mdbasic.lst`, top-level `mdbasic.prg`/`mdbasic.crt`, `tools/cart_boot.bin`); distributables ship via GitHub Releases. Rebuild locally rather than expecting them in the tree. The one exception is `mdbasic.d64`, which IS tracked — it is the template disk (upstream's example library) that `build_disk.sh` copies and swaps the fresh PRG into.
- The version string lives in the `mesge` banner (`.text "mdbasic 26.06.17"`); bump it for releases.
- Commit messages follow `version YY.MM.DD ...` / `BUGFIX:` / `CHANGE:` style (see git log).
